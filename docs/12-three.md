# 12. 3D на three.js: частицы и стекло

**Зачем:** фоны из главы 04 — это один прямоугольник и фрагментный шейдер. Здесь — настоящая
3D-сцена: камера, тысячи частиц, прозрачный объект с преломлением. Главную работу делает
**вершинный** шейдер.

| Эффект | Что внутри | Файл |
| --- | --- | --- |
| Галактика | 50 000 точек, вращение рукавов в вершинном шейдере | `src/runtime/three/galaxy.js` |
| Рой | Вихрь частиц + поток, притяжение к курсору | `swarm.js` |
| Морфинг | Логотип из частиц ↔ сфера / тор / куб / волна | `morph.js` |
| Текст из частиц | Текст рассыпается и собирается, курсор расталкивает | `text-particles.js` |
| Стекло | `MeshPhysicalMaterial`: преломление, матовость, дисперсия | `glass.js` |

## Зачем three.js, если раньше обходились без него

Для одного прямоугольника хватает 500 строк своего рантайма. Для 3D нужно намного больше:
матрицы камеры и перспективы, буферы геометрии, физически корректный материал стекла (он
рисует сцену за объектом в отдельную текстуру и читает её со сдвигом), карта окружения для
отражений. Всё это в three.js уже есть и проверено миллионами сайтов.

Цена — около 187 КБ gzip. Поэтому:

- в Студии three.js грузится **лениво** — только когда вы выбрали 3D-эффект (`import('three')`);
- на главной странице его нет вообще;
- в вашем проекте он ставится один раз (`npm i three`), и все 3D-эффекты используют его вместе.

## Устройство: рантайм сцены + эффект

Как и для шейдерных фонов, всё общее вынесено в рантайм — `src/runtime/scene.js`:

```js
const effect = createScene(THREE, canvas, galaxy, { values }, { mouse: true, quality: 1.5 })
```

| Рантайм (`scene.js`) берёт на себя | Эффект (`galaxy.js`) отвечает за |
| --- | --- |
| `WebGLRenderer`, камеру, тональную компрессию (ACES) | что лежит в сцене |
| размер холста, потолок DPR, адаптивное качество | как это движется (`update`) |
| мышь с инерцией (−1…1), наведение, прокрутку | реакцию на новые параметры (`set`) |
| паузу за экраном, «уменьшить движение» | уборку своих ресурсов (`dispose`) |
| статистику для панели FPS, уборку видеопамяти | |

**three.js передаётся параметром** (`THREE`), а не импортируется внутри. Зачем: файлы
`scene.js` и `galaxy.js` без `import`, их текст Студия вставляет в экспорт, а сверху
дописывает одну строку `import * as THREE from 'three'`. Один и тот же код работает в Студии
и у вас.

Эффект — функция, которая получает контекст и возвращает три метода:

```js
export function galaxy({ THREE, scene, camera, renderer, values, helpers }) {
  // 1. Наполнить сцену
  const points = new THREE.Points(geometry, material)
  scene.add(points)
  return {
    update({ time, dt, pointer, scroll, hover, progress }) { /* каждый кадр */ },
    set(values) { /* поменялись ползунки */ },
    dispose() { /* освободить своё */ },
  }
}
```

## Вершинный шейдер — главный герой

Вспомним главу 02: вершинный шейдер решает, **где** точка, фрагментный — **какого она цвета**.
В фонах вершин было три (один треугольник). Здесь каждая частица — вершина, и их 50 000.

### Почему не двигать частицы в JavaScript

Можно каждый кадр пересчитывать 50 000 позиций в JS и отправлять массив в видеокарту.
Это 150 000 чисел на кадр через шину — процессор занят, кадры падают.

Вместо этого JavaScript **один раз** раскладывает начальные позиции, а движение считает
вершинный шейдер — формулой от времени. Каждый кадр в видеокарту уходит одно число `uTime`.

### Галактика: дифференциальное вращение

```glsl
attribute float aScale;      // свой размер у каждой звезды (из JS, один раз)
attribute vec3 aColor;       // свой цвет
uniform float uTime;         // одно число на кадр
void main() {
  float r = length(position.xz);                                    // расстояние до центра
  float angle = atan(position.z, position.x) + uTime * uSpin / (r + 0.35);
  vec3 p = vec3(cos(angle) * r, position.y, sin(angle) * r);        // повернули
  vec4 view = modelViewMatrix * vec4(p, 1.0);
  gl_Position = projectionMatrix * view;
  gl_PointSize = uSize * aScale * 22.0 / -view.z;                   // дальше — меньше
}
```

- `attribute` — данные **каждой** вершины (позиция, цвет, размер). `uniform` — одно на всех.
- Угол поворота делится на `r`: звёзды у центра вращаются быстрее, внешние отстают — рукава
  закручиваются, как у настоящих галактик.
- `modelViewMatrix`, `projectionMatrix` — матрицы, которые three.js передаёт сам: «где объект» и
  «как камера видит» (перспектива).
- `gl_PointSize / -view.z` — размер точки обратно пропорционален расстоянию до камеры:
  ближние звёзды крупнее.

**Раскладка звёзд** (в JS, один раз):

```js
const r = Math.pow(Math.random(), 1.6) * radius          // больше звёзд у центра
const arm = ((i % arms) / arms) * Math.PI * 2             // угол рукава
const bend = r * curl                                      // рукав изогнут: чем дальше, тем больше угол
const spread = () => Math.pow(Math.random(), 3) * (±1) * randomness * r   // большинство — у оси рукава
```

`Math.pow(Math.random(), 3)` — приём, который стоит запомнить: случайное число в степени
прижимает значения к нулю. Большинство звёзд лежит у оси рукава, редкие — далеко.

### Мягкая светящаяся точка

```glsl
float d = length(gl_PointCoord - 0.5);                    // расстояние от центра точки
float a = pow(1.0 - smoothstep(0.0, 0.5, d), 2.2);         // яркий центр, мягкий край
gl_FragColor = vec4(vColor * a, a);
```

`blending: AdditiveBlending` — цвета точек **складываются**. Где звёзд много, получается яркое
свечение без всякой постобработки. `depthWrite: false` — точки не закрывают друг друга.

### Рой: вихрь + поток + курсор

```glsl
float angle = uTime * (0.25 + aSeed.w * 0.35) / (0.4 + r * 0.35);   // вихрь
p.xz = mat2(cos(angle), -sin(angle), sin(angle), cos(angle)) * p.xz;
p += flow(p * 0.8, uTime * 0.6) * 0.32;                              // струи
// Притяжение к курсору: сильнее вблизи
vec3 toMouse = uMouse - p;
float pull = uAttract * uMouseActive * exp(-length(toMouse) * 0.9);
p += normalize(toMouse) * min(length(toMouse) * 0.9, 1.6) * pull;
```

**Курсор в 3D.** Мышь — это точка на экране, а частицы — в пространстве. `Raycaster` строит
луч из камеры через курсор, и мы находим, где он пересекает плоскость z = 0. Эта точка и
уходит в шейдер как `uMouse`.

На этом эффекте мы наступили на грабли: первая версия двигала частицы сильным полем потока
(`p += flow(p) * 1.1`), и облако «складывалось» вдоль одной плоскости — снизу появлялся ровный
срез. Сильное смещение по детерминированному полю сминает пространство. Решение — основное
движение сделать вращением (оно сохраняет форму), а поток оставить слабым.

### Морфинг: две позиции у каждой частицы

```js
geometry.setAttribute('position', from)   // точки в логотипе
geometry.setAttribute('aTo', to)          // точки на сфере
geometry.setAttribute('aDelay', delay)    // своя задержка
```

```glsl
float t = smoothstep(aDelay * 0.4, aDelay * 0.4 + 0.6, uMorph);   // своё «окно» в общем прогрессе
vec3 p = mix(position, aTo, t);
p += vec3(sin(…), cos(…), sin(…)) * sin(t * 3.14159) * uChaos * 0.6;   // вихрь в пути
```

- `smoothstep` с задержкой: каждая частица летит в свой отрезок общего прогресса. Задержка
  зависит от x логотипа — превращение идёт **волной слева направо**.
- `sin(t·π)` — 0 в начале, 1 в середине, 0 в конце. Частицы «вихрятся» только в пути, а
  логотип и сфера остаются чёткими.

**Точки логотипа.** Текст рисуется на скрытом 2D-холсте (`fillText`), затем `getImageData`
даёт все пиксели; берём случайные непрозрачные. Помощник `samplePixels` в `scene.js`. Так же
можно взять любую картинку (логотип в PNG).

**Точки на сфере — равномерно.** Наивно (случайные широта и долгота) точки собираются у полюсов.
Правильно: `z` — равномерно от −1 до 1, угол — равномерно, радиус круга на этой высоте
`√(1 − z²)`. Это теорема Архимеда: площадь пояса сферы зависит только от его высоты.

**Прогресс:** «Само» (туда-обратно по косинусу), «Наведение», «Прокрутка» или из кода —
`effect.progress(0.5)`; `effect.progress(null)` возвращает управление эффекту.

### Текст из частиц

То же, что морфинг, но вторая позиция — «разлёт»: у каждой точки случайное направление
(равномерно по сфере) и своя скорость. Курсор **всегда** расталкивает точки рядом с собой:

```glsl
vec2 away = p.xy - uMouse.xy;
p.xy += normalize(away) * uRepel * 0.6 * exp(-dot(away, away) * 4.0);
```

`exp(−d² · 4)` — «колокол» (гауссиана): сильно рядом с курсором, почти ноль уже через полединицы.

**Узкий экран.** Текст шириной 5 единиц на телефоне не влезает. `helpers.visibleWidth(camera)`
считает, сколько единиц видно по ширине на глубине 0:

```js
2 · расстояние · tan(угол обзора / 2) · соотношение сторон
```

и при `resize` эффект уменьшает себя, чтобы текст влез с полями.

## Стекло: физический материал

```js
const material = new THREE.MeshPhysicalMaterial({
  transmission: 1,     // пропускает свет — стекло
  thickness: 1.2,      // «толщина»: насколько сильно сдвигается то, что за ним
  ior: 1.5,            // показатель преломления: вода 1.33, стекло 1.5, алмаз 2.42
  roughness: 0.05,     // матовость: размытие того, что за стеклом
  dispersion: 3,       // радуга: разный ior для красного, зелёного и синего
})
```

Как three.js это делает: перед кадром рисует **все непрозрачные объекты** в отдельную
текстуру, а при отрисовке стекла читает её со сдвигом по нормали поверхности. Поэтому
**за стеклом обязательно должно что-то быть** — иначе преломлять нечего. У нас это плоскость с
яркими полосами и текстом (рисуются на 2D-холсте → `CanvasTexture`).

**Отражения.** Без них стекло выглядит как «дырка». `RoomEnvironment` — встроенная в three.js
«комната» с источниками света; `PMREMGenerator` один раз превращает её в карту окружения
(`scene.environment`), и все материалы сцены получают реалистичные блики.

В панели FPS у «Стекла» `draw 3`: фон для текстуры преломления, фон на экран, стекло.

## Стеклянные фигуры

Россыпь стеклянных кубов, шаров, капсул и колец — тот же физический материал, что у «Стекла».
У каждой фигуры «дом» и пружина к нему; поведение:

| Режим | Что происходит |
| --- | --- |
| Мышь | Курсор — точка в 3D; фигуры отталкиваются с силой `1 / (0.5 + d²)` |
| Прокрутка | «Дом» сдвигается по высоте пропорционально прокрутке и «глубине» фигуры — параллакс; вращение ускоряется |
| Клик | `Raycaster` из камеры через точку клика: попал — фигура подпрыгивает и крутится; мимо — все получают толчок от точки клика и пружиной возвращаются |
| Плавают | Только покачивание |

Скруглённый куб — обычный `BoxGeometry` с разбиением 4×4×4, вершины которого притянуты к сфере
на долю «Скругления».

## Экспорт 3D-эффекта

```js
/** Галактика — сгенерировано в 3D-конструкторе … */
// Нужен three.js 0.186.1: npm i three@0.186.1 — или import map из index.html.
import * as THREE from 'three'

export function createScene(THREE, canvas, setup, spec, options) { … }   // scene.js
export function galaxy({ THREE, scene, … }) { … }                        // эффект
const VALUES = { … }
export function mount(target, options) { … }
```

**Со сборщиком** (Vite, webpack, Next): `npm i three@0.186.1` — и всё.

**Без сборщика** (обычный HTML, Tilda): браузер не знает, что такое `'three'`. Import map
объясняет:

```html
<script type="importmap">
  {
    "imports": {
      "three": "https://cdn.jsdelivr.net/npm/three@0.186.1/build/three.module.js",
      "three/addons/": "https://cdn.jsdelivr.net/npm/three@0.186.1/examples/jsm/"
    }
  }
</script>
```

Версия зафиксирована — та, с которой проверена Студия (её подставляет `vite.config.ts` из
`node_modules/three/package.json`). Без фиксации однажды выйдет новая версия three с
изменениями, и эффект сломается без единой правки с вашей стороны.

Тест «экспортированный 3D-эффект работает на чистой странице» берёт import map прямо из
сниппета и подменяет CDN файлами из `node_modules` — проверка не зависит от интернета.

## Уборка видеопамяти

WebGL-ресурсы **не собираются сборщиком мусора** JavaScript. Если просто удалить холст,
геометрии и текстуры останутся в видеопамяти до закрытия вкладки. `destroy()` обходит сцену:

```js
scene.traverse((object) => {
  object.geometry?.dispose()
  for (const material of [object.material].flat()) {
    for (const value of Object.values(material)) if (value?.isTexture) value.dispose()   // карты материала
    material.dispose()
  }
})
renderer.dispose()
renderer.forceContextLoss()   // отпустить контекст сразу (лимит ~16 на страницу)
```
