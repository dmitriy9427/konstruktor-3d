# 08. Производительность

**Зачем:** красивый фон, из-за которого тормозит прокрутка и греется ноутбук, хуже, чем никакой.

## Панель в углу

На сайте — только при разработке:

```ts
if (import.meta.env.DEV) void import('../engine/perf').then((m) => m.mountPerf())
```

При сборке Vite заменяет `import.meta.env.DEV` на `false`, условие становится `if (false)`, и
код панели выбрасывается из бандла целиком. В Студии панель включается переключателем «FPS».

```
60 FPS · эффектов: 1
память JS 11 МБ
Волны
CPU 0.10 мс · GPU 0.57 мс
846×807 · dpr 1.00 · draw 1
```

| Строка | Что значит | Хорошо |
| --- | --- | --- |
| **FPS** | Кадров в секунду у всей страницы. Зелёный ≥ 55, жёлтый ≥ 40, красный — ниже | 60 (или частота экрана) |
| **эффектов** | Сколько эффектов сейчас живёт | Столько, сколько вы ждёте. Больше — забыли `destroy()` |
| **память JS** | Только Chrome | Не растёт со временем |
| **CPU** | Сколько миллисекунд кадра занял JavaScript эффекта | < 0.5 мс |
| **GPU** | Сколько работала видеокарта (не везде доступно) | < 4 мс |
| **846×807** | Размер холста в настоящих пикселях | — |
| **dpr** | Фактическая плотность (с учётом потолка и адаптивного снижения) | 1–1.5 для фонов |
| **draw** | Вызовов отрисовки за кадр: 1 — только эффект, 2 — плюс постобработка | 1–2 |

На кадр при 60 FPS есть **16,6 мс** на всё: JavaScript страницы, стили, раскладку, отрисовку.
Фон должен брать из них как можно меньше.

## Как панель узнаёт об эффектах

Каждый эффект кладёт свою статистику в общий реестр:

```js
const registry = (globalThis.__K3D_EFFECTS__ ??= new Set())
registry.add(stats)       // при создании
registry.delete(stats)    // при destroy()
```

Через `globalThis` — потому что экспортированные эффекты лежат в **разных** файлах и не
импортируют друг друга. Панель раз в полсекунды читает реестр и перерисовывает текст.

## Приёмы, которые уже встроены

1. **Потолок DPR.** Мягкому фону ретина не нужна. `quality: 1.5` на экране с DPR 3 —
   вчетверо меньше пикселей.
2. **Адаптивное качество.** Полсекунды подряд кадры дольше 24 мс — плотность снижается на 0.15
   (до 0.5).
3. **Пауза за экраном.** `IntersectionObserver`: эффект ниже по странице не рисует ничего.
4. **Кадры по требованию.** «Уменьшить движение» или пауза — кадр рисуется, только когда
   что-то поменялось.
5. **Один треугольник, один проход.** Постобработка — второй проход, только если включена.
6. **Кеш uniform.** Места переменных ищутся один раз.
7. **Ленивая загрузка.** Код и WebGL — только когда блок рядом.

## Что делать, если тормозит

| Симптом | Попробуйте |
| --- | --- |
| GPU > 8 мс | Снизить «Качество» до 1; меньше «Масштаб»/деталей; выключить свечение (24 чтения текстуры на пиксель) |
| Тормозит только на ретине | «Качество» 1–1.25 |
| Тормозит при прокрутке | Проверить, что под холстом нет `backdrop-filter` и огромных теней |
| Несколько эффектов на странице | Ленивая загрузка; не больше 2–3 видимых одновременно |
| Растёт «эффектов» | Где-то нет `destroy()` при уходе со страницы (SPA) |

## Как мерить честно

- Панель Performance в DevTools: запись 5 секунд, смотреть «GPU» и длинные кадры.
- Включить в DevTools «CPU throttling 4×» — так видно слабые телефоны.
- Время GPU с расширением бывает недоступно (Safari, Firefox) — там смотрите на FPS и
  адаптивный dpr: если он упал ниже `quality`, кадры не успевали.
