# 09. Свой эффект: «Плазма» с нуля

**Зачем:** пройти весь путь от пустого файла до эффекта в каталоге, с экспортом и тестами.
«Плазма» (`src/effects/plasma.ts`) сделана ровно по этому рецепту.

## Шаг 1. Файл с описанием

```ts
// src/effects/plasma.ts
import type { EffectDef } from './types'

export const plasma: EffectDef = {
  id: 'plasma',                  // в адресе: ?e=plasma, тег веб-компонента: <k3d-plasma>
  name: 'Плазма',
  category: 'Фоны',              // раздел каталога
  kind: 'quad',                  // полноэкранный шейдер
  description: 'Переливы из суммы синусов — классика демосцены',
  usesMouse: true,               // показать переключатель «Следовать за мышью»
  params: {},
  fragment: /* glsl */ `
void main() {
  fragColor = vec4(1.0, 0.0, 0.5, 1.0);
}`,
}
```

`/* glsl */` перед строкой — подсказка редактору: с расширением для GLSL код внутри
подсвечивается.

## Шаг 2. В каталог

```ts
// src/effects/index.ts
import { plasma } from './plasma'

export const EFFECTS: EffectDef[] = [noise, lava, waves, clouds, space, aurora, plasma, imageDistort, tilt]
```

Откройте `studio.html?e=plasma` — розовый экран. Эффект уже в каталоге, у него работает
«Забрать код», ссылка, панель FPS. Мы не трогали ни одного компонента.

## Шаг 3. Узор: сумма синусов

```glsl
void main() {
  vec2 p = (gl_FragCoord.xy - 0.5 * uResolution) / uResolution.y * 6.0;
  float t = uTime * 0.6;
  float v = sin(p.x + t)                         // вертикальные полосы
          + sin(p.y * 0.8 - t * 1.3)             // горизонтальные
          + sin((p.x + p.y) * 0.6 + t * 0.7)     // диагональные
          + sin(length(p) * 1.4 - t * 2.0);      // круги от центра
  v *= 0.25;                                     // сумма четырёх синусов: −4…4 → −1…1
  fragColor = vec4(vec3(0.5 + 0.5 * v), 1.0);
}
```

Четыре волны в разные стороны складываются — где совпали гребни, светло, где впадины — темно.
Узор живой, потому что у каждой волны своя скорость.

## Шаг 4. Ползунки вместо чисел

Каждое «магическое число» — кандидат в параметр:

```ts
params: {
  speed: { type: 'number', label: 'Скорость', min: 0, max: 3, step: 0.01, default: 0.6 },
  scale: { type: 'number', label: 'Масштаб', min: 1, max: 20, step: 0.1, default: 6 },
  bands: { type: 'number', label: 'Полосы', min: 0.2, max: 3, step: 0.01, default: 1 },
  glow: { type: 'number', label: 'Блики', min: 0, max: 1, step: 0.01, default: 0.6 },
  colorA: { type: 'color', label: 'Тень', default: '#0d0626' },
  colorB: { type: 'color', label: 'Основной', default: '#7c4dff' },
  colorC: { type: 'color', label: 'Блик', default: '#ff7ac6' },
},
```

В шейдере они сразу доступны как `uSpeed`, `uScale`, `uBands`, `uGlow`, `uColorA`… — объявлять
не нужно, рантайм сделает это сам.

Как выбрать диапазон: `min`/`max` — границы, за которыми эффект **ломается или становится
некрасивым**. «Случайно» берёт числа из середины (15–85 % диапазона), поэтому слишком широкий
диапазон — это частые некрасивые случайные наборы.

## Шаг 5. Цвет: градиент из трёх цветов

Сырая радуга (`cos` с разными сдвигами по каналам) даёт грязные оливковые пятна. Надёжнее
раскрасить узор своими цветами:

```glsl
float f = 0.5 + 0.5 * sin(v * 6.2832);                  // узор → волна 0…1
vec3 col = mix(uColorA, uColorB, smoothstep(0.0, 0.65, f));   // тень → основной
col = mix(col, uColorC, smoothstep(0.7, 1.0, f) * uGlow);     // + блики на гребнях
```

`sin(v × 2π)` превращает узор в повторяющиеся полосы; `uBands` (множитель `v`) решает, сколько
их на экране.

## Шаг 6. Мышь

```glsl
vec2 orbit = vec2(sin(t * 0.7), cos(t * 0.5)) * uScale * 0.3;       // центр ходит сам
vec2 mouse = (uMouse - 0.5) * vec2(uResolution.x / uResolution.y, 1.0) * uScale;
vec2 c = mix(orbit, mouse, uMouseActive);                            // …или за курсором
… sin(length(p - c) * 1.4 - t * 2.0) …                              // круги — от c
```

`uMouseActive` плавно идёт от 0 к 1, когда курсор над холстом, — центр мягко «перетекает» к
мыши и обратно. Если мышь выключена в настройках, `uMouseActive` всегда 0.

## Шаг 8. Проверка

```bash
npm test     # каталог: уникальный id, пресеты ссылаются только на известные параметры,
             # «Случайно» даёт допустимые значения, экспорт импортируется как модуль
npm run e2e  # эффект открывается, шейдер компилируется, кадр не пустой, ошибок в консоли нет
```

Тесты перебирают `EFFECTS` — новый эффект проверяется **автоматически**, писать тест не нужно.
Опечатка в пресете (`colourA` вместо `colorA`) уронит `npm test`, ошибка в GLSL — `npm run e2e`.

## Чек-лист хорошего эффекта

- [ ] Первый кадр красивый (если нет — `startTime` в описании или другие умолчания).
- [ ] Пропорции через `/ uResolution.y` — круги не вытягиваются.
- [ ] Нет деления на ноль (`max(…, 1e-5)`).
- [ ] Циклы до константы, переменная граница — через `if (…) break;`.
- [ ] В панели FPS: GPU < 4 мс на 1080p при `quality` 1.5.
- [ ] Все три пресета разные по настроению, а не только по цвету.
- [ ] «Случайно» пять раз подряд — ни одного уродливого результата.
