# 04. Эффекты

**Зачем:** понять, как устроен каждый эффект, и что на самом деле меняет каждый ползунок.
Код — `src/effects/*.ts`, поле `fragment`.

## «Шум» — `noise.ts`

**Идея:** domain warping — шум от координат, сдвинутых шумом (глава 02, шаг 9). Формы
закручиваются, как дым.

```glsl
vec2 q = vec2(fbm(p + t), fbm(p + vec2(5.2, 1.3) - t));   // первое искажение
vec2 r = vec2(fbm(p + uWarp * q + …), fbm(p + uWarp * q + …)); // искажение искажения
float n = fbm(p + uWarp * r);                              // итоговый узор
n = clamp((n - 0.5) * uContrast + 0.5, 0.0, 1.0);          // контраст вокруг середины
```

| Параметр | Что меняет |
| --- | --- |
| Скорость | Как быстро течёт узор |
| Масштаб | Крупные клубы (меньше) или мелкие разводы (больше) |
| Закрутка (`warp`) | Насколько сильно координаты искажены: 0 — простое облако, 3–4 — мраморные вихри |
| Контраст | Резкость переходов между цветами |
| Цвета 1–3 | Тень, основной, акцент (цвет 3 появляется там, где и узор, и первое искажение `q` сильные) |

Мышь притягивает разводы к себе.

## «Лава» — `lava.ts`

**Идея:** расплавленный поток — водовороты, слоистые кольца, тонкие прожилки, раскалённое до
белого ядро и тёмная остывшая корка. Как на фото извергающейся лавы.

Основа — «шум от шума», как в «Шуме»: координаты искажаются шумом дважды (`q`, `r`), и узор
закручивается в водовороты. Сверху три добавки:

- **Кольца** — синус от искажённого поля: `sin(f · частота · 2π)`. Там, где поле меняется
  плавно, синус рисует концентрические полосы вокруг водоворота — слои потока.
- **Прожилки** — мелкий шум, **растянутый** в 13 раз по одной оси. Ось берётся из направления
  искажения `r`, поэтому волокна текут вдоль потока, а не просто лежат полосами.
- **Жар** — итоговое число — это «температура», и она переводится в цвет по шкале:
  корка → тёплая лава → жар → белое ядро. Самое горячее ещё и светится (`pow(temp, 3)` —
  свечение только у самых горячих мест).

**Перспектива:** верх кадра сжимается (`1 / (1 − y · наклон)`) — плоскость уходит вдаль, как
3D-сцена, без 3D. Даль ещё и чуть темнее.

**Мышь размешивает:** точки вокруг курсора поворачиваются на угол, который быстро убывает с
расстоянием (`exp(−d²·6)`). Получается водоворот, который тянет за собой узор.

| Параметр | Что меняет |
| --- | --- |
| Скорость, Направление течения | Как и куда течёт |
| Масштаб, Закрученность | Размер и сила водоворотов |
| Кольца, Частота колец | Слоистость |
| Прожилки | Волокна вдоль потока |
| Жар, Контраст | Сколько раскалённой лавы и насколько резко она переходит в корку |
| Свечение | Яркость горячих мест |
| Перспектива | 0 — сверху, 1 — плоскость уходит вдаль |
| Мышь размешивает | Сила водоворота у курсора; меньше нуля — в другую сторону |

Пресеты: вулкан, застывающая, солнце, голубое пламя, мрамор (те же кольца и прожилки в серых
тонах — это уже камень).

## «Клетки» — `cells.ts`

Бывшая «Лава». **Идея: метаболы.** У каждой капли есть «поле силы», которое убывает с расстоянием:

```glsl
field += r * r / dot(d, d);     // r — радиус капли, d — от капли до пикселя
```

Поля всех капель **складываются**. Где сумма больше 1 — там капля. Когда две капли сближаются,
между ними сумма полей тоже больше 1 — появляется плавная перемычка. Капли не пересекаются
кругами, а **сливаются** — как клетки под микроскопом или лава-лампа.

Каждая капля ходит по своей фигуре Лиссажу; ещё одна «сидит» на курсоре.

## «Волны» — `waves.ts`

**Идея:** море до горизонта с небом и солнцем — и вода, которая **откликается**: мышь
толкает её, клик бросает каплю, «Дождь» роняет капли сам. Два шейдера.

### 1. Живая вода — симуляция

Высота «живой» воды хранится в текстуре 256×256 — это участок моря перед камерой (8×8
единиц). Каждый кадр отдельный шейдер считает новый шаг по классической схеме волнового
уравнения (её описал Хьюго Элиас в 1990-х, ей до сих пор делают воду в играх):

```glsl
vec4 s = texture(uState, uv);                      // r — высота сейчас, g — шагом раньше
float sum = соседи слева + справа + сверху + снизу;
float h = (sum * 0.5 - s.g) * uDamping;            // волна «перетекает» к соседям
fragColor = vec4(h, s.r, 0.0, 1.0);                // новая высота и «прошлая» для следующего шага
```

Почему это волна: если соседи выше, чем мы были шаг назад, — поднимаемся, если ниже —
опускаемся. Возмущение расходится кругом. `uDamping` < 1 — каждый шаг энергия чуть теряется,
и круги гаснут.

- **Мышь:** точка воды под курсором опускается «колоколом», сила — от скорости движения
  (`uMouseVel`): провёл быстро — бурун, медленно — лёгкий след.
- **Клик:** рантайм передаёт нажатия в шаг симуляции (`uClicks`) — капля в точке клика.
- **Дождь:** на каждом шаге 8 случайных мест; с вероятностью `0.35 · дождь²` туда падает
  маленькая капля. В кадре — падающие штрихи: три слоя «сеток» из вытянутых ячеек, в части
  ячеек — капля со своей фазой (ближний слой крупнее и быстрее), «Наклон дождя» поворачивает их.
  Свежая капля оставляет на воде светлый всплеск.
- **Пинг-понг:** читать и писать одну текстуру нельзя, поэтому их две — шаг читает одну,
  пишет в другую, потом они меняются местами.
- **60 шагов в секунду** при любой частоте экрана: на мониторе 120 Гц круги не бегут вдвое быстрее.
- Нужен рендер в float-текстуру (`EXT_color_buffer_float`); где его нет — вода без кругов,
  остальное работает.

### 2. Картинка

Для каждого пикселя — луч камеры. «Линия горизонта» поднимает и опускает взгляд.

**Высота солнца** — в долях видимого неба (0 — горизонт, 1 — верх кадра). Раньше она была в
градусах, и при высоком солнце оно уходило за верх кадра — казалось, что ползунок не работает.

**Небо:** градиент, солнечный диск, два ореола (`exp(−угол / ширина)`), вспышка молнии.

**Вода.** Первая версия складывала синусоиды — и на воде были видны **длинные прямые
полосы**: синусоида — это бесконечно длинный прямой гребень. Теперь вал строится иначе:

```glsl
float swell(vec2 p, float sharp) {
  p += 1.2 * (vec2(noise(p * 0.5), noise(p * 0.5 + 7.3)) - 0.5) * 2.0;  // гребень гнётся
  vec2 w = 1.0 - abs(sin(p));          // острые вершины, пологие впадины
  w = mix(w, abs(cos(p)), w);          // скругляем впадины
  return pow(1.0 - pow(w.x * w.y, 0.65), sharp);
}
```

Аргумент синусоиды сдвинут шумом — гребни изгибаются и рвутся. 5 октав, каждая мельче,
слабее и повёрнута на ~37°; всё сжато вдоль горизонта («Вытянутость») — валы лежат поперёк
взгляда, как в открытом море. Мелкие октавы вдали гаснут (они мельче пикселя).

**Свет:** вода — это в основном **отражённое небо** (Френель), а не «синяя краска»: поэтому
картинка мягкая, без резкого контраста, и цвет воды сам меняется вместе с небом. Блики солнца
— `pow(отражение · солнце, 600)`. Дымка растворяет даль в небе у горизонта.

### Дождь и молнии

- **Капли в кадре** — штрихи в трёх слоях: каждый слой — сетка вытянутых ячеек, в части ячеек
  капля со своей фазой; ближний слой крупнее и быстрее. «Наклон дождя» поворачивает их.
- **Круги по всему морю** — не симуляцией (она покрывает только участок у камеры), а
  формулой: вода разбита на ячейки 0,55×0,55, в каждой капля падает в свой момент; кольцо
  `sin((d − r)·50)` расходится и гаснет. Вдали, где кольца мельче пикселя, видна только
  вспышка в момент удара — капли «падают» до самого горизонта.
- **Вдали** кольца мельче пикселя, а увеличивать их нельзя: кольцо вылезает за свою ячейку и
  обрезается её краями — на воде проступают квадраты (мы на это наступили). Поэтому дальние
  капли — отдельные всплески-искры в координатах **экрана**: сетка ячеек, в каждой — вспышка в
  свой момент.
- **Сверху** («Бассейн») капли летят на зрителя — штрихов почти нет, видны только круги.
- **Шторм:** валы в 3,4 раза выше и длиннее, гребни острее, бегут быстрее, а камера **качается**
  (параметр «Качка» — и в любой сцене): поднимается, кивает, заваливается — как с палубы.
- **Объём волн.** Раньше вода была плоскостью, а волны — только светом. Теперь луч камеры
  **идёт по карте высот** (heightfield raymarch): шагаем вдоль луча, пока он не окажется под водой.
  Ближний вал закрывает воду за собой. Для поиска хватает 2 крупных октав, а начинаем с высоты
  самого высокого гребня — так шагов меньше (на ретине ≈ 5–6 мс видеокарты).
- **Молнии:** время делится на слоты по 1,7 с; в части слотов (по «Молнии») — вспышка с
  двойным мерцанием и разряд: ломаная `x = x0 + fbm(y) + noise(y·30)` от верха кадра до
  воды. У каждого удара своё расстояние: ближний разряд касается воды ниже на экране, он
  толще, а в точке удара расходится вспышка. Вспышка подсвечивает небо — и воду, потому что вода отражает небо.

### Время суток

Таблица из 5 сцен (рассвет, день, закат, шторм, ночь): цвета неба, воды, солнца, его высота,
дымка, «штормовость». Режимы:

| Режим | Что задаёт сцену |
| --- | --- |
| Свои | Цвета и солнце из параметров |
| Ползунок | «Сцена» 0…4, дробное — смесь соседних |
| Прокрутка | `uScroll · 4`: пока блок проезжает по экрану — рассвет → день → закат → шторм → ночь |
| Само | По кругу со временем, после ночи снова рассвет |

В сцене «шторм» дождь и молнии включаются сами, волны выше, солнце за тучами.

**Прокрутка — с прилипанием.** Если блок просто едет вместе со страницей, вода уезжает
вверх раньше, чем успеет смениться день. Поэтому в режиме «Прокрутка» эффект кладут в
**липкий стек** (как у переходов, глава 11): холст `position: sticky` прилипает к экрану, а
поверх него едут сцены. Прогресс — насколько прокручен стек, его рантайм считает сам:

```js
mount(document.querySelector('#sea'), { scrollStack: document.querySelector('.day-cycle') })
// uScroll = (верх экрана − верх стека) / (высота стека − высота экрана)
```

Разметку и CSS стека Студия кладёт в `index.html`. В превью Студии это мини-страница: её
можно листать прямо в превью.

| Параметр | Что меняет |
| --- | --- |
| Скорость, Частота, Высота, Острота гребней | Сами волны |
| Вытянутость вдоль горизонта, Мелкая рябь | Форма валов |
| Линия горизонта | 0 — смотрим на воду сверху, 1 — горизонт посередине |
| Время суток, Сцена, Скорость смены суток | См. выше |
| Дымка, Солнце (высота, сторона, размер), Блики | Свет |
| Дождь, Наклон дождя, Молнии | Погода |
| Мышь толкает воду, Сила и размер капли, Затухание кругов | Живая вода |

## «Облака и дым» — `clouds.ts`

**Плотность** — «шум от шума»: координаты fbm искривлены другим fbm, формы клубятся.
«Клубление» меняет их на месте, «Ветер» и «Направление ветра» несут.

**Кучевые облака — шум Перлина и Ворли.** Обычный `fbm` из общих функций — это value-шум: в
узлах сетки случайные *числа*, и облака выходят «размытыми пятнами». У шума **Перлина** в узлах
случайные *направления* (градиенты) — рисунок чище. Шум **Ворли** — расстояние до ближайшей из
случайных точек: круглые ячейки, из которых получаются пухлые клубы. Классический для облаков
приём — **Перлин-Ворли**: крупную форму даёт Перлин, а края «обкусывают» клубы Ворли:

```glsl
float cumulus(vec2 p) {
  float pf = perlinFbm(p * 0.8);
  float wf = worleyFbm(p * 1.6);
  return clamp((pf - (1.0 - wf) * 0.55) / 0.55, 0.0, 1.0);
}
```

Виды: **кучевые** (Перлин-Ворли), **перистые** (value-шум с закруткой), **дым**. Покрытие 0 —
чистое небо (пресет «Ясно»).

**Облака: свет как в жизни.** От каждой точки делаем 3 шага в сторону солнца и складываем
плотность по пути. Чем её больше, тем меньше света дошло — **закон Бера**:

```glsl
for (int s = 1; s <= 3; s++) acc += density(q + toSun * float(s), far, false);
float light = exp(-acc * uAbsorption * 0.8);
vec3 cloud = mix(uShadow, uLight, light);
```

Края к солнцу — светлые, толща — тёмная, тонкие края против солнца светятся («серебряная
кромка»). Для шагов света берём дешёвую плотность без мелких клочьев — разницы не видно, а
кадр вдвое дешевле.

**Дым** искривляет координаты **дважды** — клубы вытягиваются в завитки и пряди. Солнцем он не
освещается: светится сам по плотности и полупрозрачен — слои складываются, как настоящий дым.

**Два слоя:** дальний крупнее, медленнее, в дымке — глубина.

**Мышь:** раздвигает, притягивает или закручивает (поворот вокруг курсора, сильнее вблизи).

| Параметр | Что меняет |
| --- | --- |
| Вид | Облака или дым |
| Ветер, Направление ветра, Клубление | Движение |
| Покрытие, Масштаб, Закрученность, Мягкость краёв, Детали | Форма |
| Плотность, Объём, Серебряная кромка | Свет и прозрачность |
| Солнце по X / Y, Сияние солнца | Откуда свет |
| Дальний слой | Глубина |
| Мышь, Сила и радиус мыши | Взаимодействие |

Пресеты: день, закат, гроза, дым, цветной дым, туман.

## «Космос» — `space.ts`

**Звёзды — сетка.** Плоскость делится на клетки; в каждой — максимум одна звезда в случайном
месте клетки (`hash2(номер клетки)`). Часть клеток пустая — «плотность». Три слоя разного
масштаба едут с разной скоростью («Направление полёта») — параллакс; мышь сдвигает ближние
слои сильнее.

**Туманность** течёт («Дрейф») — это шум от шума, как в «Шуме». Три формы:

| Форма | Как |
| --- | --- |
| Облако | Порог по шуму, ярче к центру |
| Волокна | «Хребты» шума: `pow(1 − |2n − 1|, 5)` — тонкие светящиеся нити |
| Кольцо | Яркость по расстоянию до центра: `exp(−(r − 0.32 + шум)²·36)` |

**Свои галактики** — параметр нового типа **«список»**: JSON-массив объектов, у каждого свои
поля (тип, место, размер, наклон, поворот, вращение, рукава, закрутка, яркость, цвет). В шейдере
— по массиву на поле: `uMyGalaxiesSize[8]`, `uMyGalaxiesColor[8]`… и `uMyGalaxiesCount`. В
Студии: «+ Галактика» → клик по превью — она встаёт туда; вкладки «Галактика 1, 2…» — настройки
каждой. Типы: спиральная, с перемычкой (бар через ядро), эллиптическая, кольцевая. Россыпь
далёких галактик выключается отдельно.

**Далёкие галактики.** Крупная сетка; в части ячеек — галактика: диск, повёрнутый и сжатый в
эллипс (наклон), рукава — **логарифмическая спираль** `cos(рукава · (угол − ln r · 2.2))`, яркое
ядро `exp(−r·9)`. Медленно вращаются и лежат в самом дальнем слое. Пресет «Глубокое поле».

**Метеоры.** Время делится на слоты; в каждом слоте (с вероятностью «Метеоры») пролетает
метеор: случайная точка старта, направление ± 15°. Голова — яркая точка, хвост — отрезок за
ней: расстояние до отрезка даёт толщину, а положение вдоль него — яркость, `(1 − s)²`, хвост
гаснет к концу и вырастает в начале полёта. Виды: **росчерк**, **огненный шар** (крупная
голова с ореолом), **искры** (хвост — цепочка точек с разбросом).

**Созвездия.** Готовые (Большая Медведица, Орион, Кассиопея, Лебедь, Лев) зашиты в шейдер
константными массивами. Своё — параметр нового типа **«точки»**:

```js
custom: { type: 'points', max: 32, default: '0.30,0.30,0;0.42,0.42,1;…' }
// x,y — доли кадра (y вверх), третье число — 1: соединить с предыдущей, 0: начать новую линию
```

Рантайм превращает его в два uniform: `uniform vec3 uCustom[32]; uniform float uCustomCount;` —
шейдер обходит точки циклом и рисует звезду и линию к предыдущей (расстояние до отрезка).

В Студии: «Рисовать» → клики по превью ставят звёзды, «Новая линия» → следующая начнёт
отдельную линию, «Отменить», «Очистить». Точки сразу в адресе и в экспорте.

Появление: **сразу** (целиком), **прорисовка** (звёзды и линии появляются по очереди и
остаются), **по кругу** (рисуется, гаснет и заново), **пульс** (линии «дышат» волной).
«Скорость прорисовки» — линий в секунду.

Прорисовка — это число «сколько линий уже нарисовано»: `drawn = (uTime − 4) · скорость`
(рантайм начинает время с 4 с). Линия номер `i` видна на `clamp(drawn − i, 0, 1)` своей длины.
Поэтому новая звезда своего созвездия появляется **сразу**: прогресс давно её обогнал.

Пресеты: глубокий космос, звездопад, огненные шары, атлас созвездий, красное кольцо, волокна.

## «Сияние» — `aurora.ts`

**Три ленты-занавеса.** У каждой — волнистый нижний край (fbm, плывущий во времени). Ниже
края — ничего, выше — свет, который затухает (`exp(−dy × k)`).

**Лучи** — шум, зависящий только от x: вдоль ленты появляются вертикальные полосы, как у
настоящего сияния.

**Цвет по высоте:** у края — цвет 1, выше — цвет 2, верхняя лента — цвет 3. Сложение лент
проходит через `1 − exp(−col)` — яркость не «выгорает» в белое.

| Параметр | Что меняет |
| --- | --- |
| Ширина волн | Насколько растянуты изгибы лент |
| Яркость | Общая сила |
| Центр по X / Y | Где сияние ярче и на какой высоте ленты — ставьте туда заголовок |

## «Плазма» — `plasma.ts`

Сумма четырёх синусов (полосы по x, по y, по диагонали и круги от центра, который ходит сам
или следует за мышью), раскрашенная градиентом «тень → основной → блик». Разобрана по шагам
в главе [09. Свой эффект](09-new-effect.md).

| Параметр | Что меняет |
| --- | --- |
| Масштаб | Размер узора |
| Полосы | Сколько цветных полос на экране |
| Блики | Насколько гребни уходят в цвет «Блик» |

## «Плывущая картинка» — `image-distort.ts`

Холст лежит **поверх** `<img>`: картинка остаётся в разметке (её видят поисковики и
пользователи без WebGL), а шейдер рисует её искажённую копию.

Сила эффекта умножается на `uHover` — плавно 0 → 1 при наведении. Без курсора фото обычное.

| Режим | Как работает |
| --- | --- |
| Волна | Координаты картинки сдвигает поле fbm — «жидкость» |
| RGB-сдвиг | Красный канал берём чуть в одну сторону от курсора, синий — в другую |
| Рябь | `sin(расстояние × 60 − время)` — круги от курсора сдвигают картинку |

| Параметр | Что меняет |
| --- | --- |
| Радиус | Зона вокруг курсора, где работает искажение |
| Приближение | Картинка чуть увеличивается при наведении — «оживает» |
| Всегда, без наведения | Эффект работает постоянно (для фонового фото) |

## «Наклон 3D» — `tilt.ts` + `src/runtime/tilt.js`

Без WebGL: только CSS `transform`. Можно повесить хоть на сто карточек.

```
курсор над карточкой → доля от центра (−1…1) → rotateX / rotateY
```

Значения догоняют цель пружиной на `requestAnimationFrame` — наклон плавный даже при рывке
мыши. **Блик** — полупрозрачный радиальный градиент (`mix-blend-mode: soft-light`), который
едет за курсором.

На тач-экранах (`hover: none`) и при «уменьшить движение» ничего не делает.

| Параметр | Что меняет |
| --- | --- |
| Угол | Максимальный наклон, ° |
| Перспектива | Меньше — сильнее «3D» (как близко камера) |
| Увеличение | Масштаб при наведении |
| Инерция | Плавность |
| Блик | Сила блика |
| Наклон от курсора | Карточка «убегает» от курсора, а не тянется к нему |
| Оси | Наклон по обеим осям или только по одной |
