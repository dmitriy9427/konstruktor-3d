# 17. Рецепты: эффект в каждый раздел

**Зачем:** [глава 09](09-new-effect.md) ведёт за руку через один фон. Здесь — карта для всех
семи разделов каталога: какие файлы трогать, что рантайм даёт готовым и на какой эффект
смотреть как на образец. В каждом образце блоки помечены комментариями
`// ── Паспорт ──`, `// ── Ползунки ──`, `// ── Пресеты ──`, `// ── Шейдер ──`.

## Главное правило

Эффект — это **данные**: объект `EffectDef` (описание, параметры, пресеты, код). Ползунки,
превью, ссылка и «Забрать код» строятся из него сами. Поэтому путь всегда один:

1. файл в `src/effects/` с `export const имя: EffectDef = { … }`;
2. строка в `src/effects/index.ts` — в массив `EFFECTS` (порядок в нём = порядок в каталоге);
3. `npm test && npm run e2e` — новый эффект проверяется автоматически.

Раздел каталога задаёт поле `category`, а **как эффект рисуется** — поле `kind`. Это разные
вещи: «Жидкость» лежит в «Курсорах», но это обычный шейдер (`kind: 'quad'`).

| Раздел | `kind` | Образец | Что ещё трогать, кроме файла эффекта и `index.ts` |
| --- | --- | --- | --- |
| Фоны | `quad` | `effects/black-hole.ts` | ничего |
| Изображения | `image` | `effects/image-glass.ts` | ничего |
| Переходы (слайды) | `slides` | `effects/shatter.ts` | ничего |
| Курсоры (шейдерные) | `quad` + `overlay: true` | `effects/cursor-ripples.ts` | ничего |
| 3D | `three` | `runtime/three/blob.js` + описание в `effects/three.ts` | `SCENE_SOURCES` в `engine/codegen.ts` |
| Интерфейс | `css` | `runtime/scramble.js` + `effects/scramble.ts` | `DOM_EFFECTS` в `codegen.ts`, превью в `studio/Preview.tsx` |
| Без WebGL | `css` | `runtime/glow.js` + `effects/glow.ts` | то же |

Первые четыре строки — **только данные**: один файл, и эффект готов. Последние три требуют
кода в `src/runtime/`, потому что рисуют не шейдером.

## Параметры: шпаргалка

```ts
params: {
  speed:  { type: 'number', label: 'Скорость', min: 0, max: 3, step: 0.01, default: 1, hint: 'Подсказка при наведении' },
  colorA: { type: 'color', label: 'Цвет', default: '#7c4dff' },
  always: { type: 'boolean', label: 'Всегда', default: false },
  mode:   { type: 'select', label: 'Режим', options: [{ value: 'a', label: 'А' }, { value: 'b', label: 'Б' }], default: 'a' },
  text:   { type: 'text', label: 'Надпись', default: 'Привет', maxLength: 24 },
  // when: параметр действует только в режиме «b» — в остальных Студия покажет его бледным с пояснением
  angle:  { type: 'number', label: 'Угол', min: 0, max: 360, default: 20, when: { mode: ['b'] } },
}
```

В шейдере ключ становится uniform-переменной: `speed` → `uSpeed` (число), `colorA` → `uColorA`
(`vec3`), `always` → `uAlways` (0 или 1), `mode` → `uMode` (номер варианта: 0, 1, 2…). В
эффектах без шейдера те же ключи приходят полями объекта `values`.

Тест каталога не пропустит «мёртвый» ползунок: параметр шейдерного эффекта обязан встречаться в
шейдере, параметр 3D-эффекта — в его функции. Исключения — то, что читает сам рантайм:
`duration`, `autoplay` (слайды) и `hideCursor` (курсоры).

## Фоны — `kind: 'quad'`

Тело фрагментного шейдера в поле `fragment`. Объявлять ничего не нужно — рантайм добавит сам:

| Что | Значение |
| --- | --- |
| `uResolution` | размер холста в пикселях |
| `uTime` | секунды |
| `uMouse`, `uMouseActive`, `uMouseVel` | курсор в долях холста (0…1, y вверх), «мышь над холстом» 0…1, скорость |
| `uHover`, `uScroll` | наведение 0…1, прокрутка блока через экран 0…1 |
| `hash`, `hash2`, `noise`, `fbm`, `rot` | случайность, плавный шум, поворот |

Образец — «Чёрная дыра»: луч света из каждого пикселя шагает сквозь пространство и гнётся к
центру. Обратите внимание на три вещи, которые нужны любому фону:

- координаты делятся на **короткую** сторону экрана — картинка не вытягивается и помещается и
  на мониторе, и на телефоне;
- `usesMouse: true` ставится, только если шейдер читает `uMouse` — иначе в сайдбаре появятся
  настройки мыши, которые ничего не делают (тест это ловит);
- `defaultCommon` задаёт свои общие настройки: дыре — лёгкое свечение, плавному градиенту —
  низкое качество и 30 кадров.

## Изображения — `kind: 'image'`

Рантайм сам загружает `<img>` из блока в текстуру `uImage` (размер — `uImageRes`), холст ложится
поверх картинки. Шейдер решает, **откуда** взять цвет пикселя:

```glsl
vec3 photo(vec2 uv) { return texture(uImage, coverUv(uv, uResolution, uImageRes)).rgb; }
```

`coverUv` — координаты «как `object-fit: cover`». Образец — «Рифлёное стекло»: сдвиг координаты
зависит от положения пикселя внутри ребра, а `uMouseActive` плавно гасит стекло вокруг курсора.

## Переходы — `kind: 'slides'`

Рантайм держит две картинки и прогресс: `fromAt(uv)` — уходящий слайд, `toAt(uv)` — приходящий,
`uProgress` идёт 0 → 1, `uDirection` — 1 вперёд, −1 назад. Параметры `duration` и `autoplay`
обязательны: их читает рантайм.

Два условия, которые шейдер обязан выполнять: при `uProgress = 0` кадр равен `fromAt(uv)`, при
`1` — `toAt(uv)`. Иначе в начале или в конце перехода картинка дёрнется.

Образец — «Осколки». Приём «обратный ход» годится для любого перехода с движением: шейдер не
двигает куски, а для каждого пикселя вычисляет, какая точка какого куска сейчас над ним.

Переходы между **секциями страницы** («Прожигание», «Шторка») устроены иначе — SVG-фильтр поверх
настоящей разметки, см. [главу 11](11-transitions.md).

## Курсоры — `overlay: true`

Шейдерный курсор — тот же `quad`, но холст прозрачный, лежит поверх страницы и пропускает клики.
Цвет пишется **уже умноженным на альфу**: `fragColor = vec4(color * a, a)`.

След должен помнить прошлое, поэтому почти всегда нужна **симуляция** — второй шейдер в поле
`simulation`. Он читает прошлое состояние из `uState` и пишет новое; рантайм делает 60 шагов в
секунду. Основной шейдер получает результат как `uSim`. Клики приходят в `uClicks[4]`.

Образец — «Круги на воде»: в текстуре высота и скорость воды, картинка — свет на склонах волн.

Лёгкие курсоры без WebGL («След», «Кольцо») — типы внутри `runtime/cursor.js`, см.
[главу 14](14-cursors.md).

## 3D — `kind: 'three'`

Код — обычный JS в `src/runtime/three/`, **без import**: его текст уходит в экспорт, а three
приходит параметром.

```js
export function blob({ THREE, scene, camera, renderer, values, helpers }) {
  // наполнить сцену
  return {
    update({ time, dt, pointer, scroll, hover }) { /* каждый кадр */ },
    set() { /* сдвинули ползунок: values уже новые */ },
    dispose() { /* то, что сцена не уберёт сама */ },
  }
}
```

Что добавить, по порядку:

1. `src/runtime/three/имя.js` и рядом `имя.d.ts` (одна строка с типом);
2. описание в `src/effects/three.ts`: `setup` — функция, `setupName` — её имя;
3. строку в `SCENE_SOURCES` в `engine/codegen.ts` — иначе экспорт не найдёт текст файла.

Образец — «Жидкая сфера». В своём `ShaderMaterial` не забудьте две строки в конце фрагментного
шейдера, иначе цвета будут не такими, как в палитре:

```glsl
#include <tonemapping_fragment>
#include <colorspace_fragment>
```

## Интерфейс и «Без WebGL» — `kind: 'css'`

Эффект вешается на обычный элемент страницы: `createИмя(el, values)` возвращает
`{ set(next), destroy() }`. Файл тоже без import. Что добавить:

1. `src/runtime/имя.js` и `имя.d.ts`;
2. описание в `src/effects/имя.ts` (`kind: 'css'`, раздел — «Интерфейс» или «Без WebGL»);
3. строку в `DOM_EFFECTS` в `engine/codegen.ts`: текст файла, имя функции, пример разметки;
4. демо в `studio/Preview.tsx`: компонент с разметкой и строка в `Preview` (выбор по `id`),
   стили демо — в `styles/studio.css`.

Образцы — «Свет по рамке» (`glow.js`) и «Шифр» (`scramble.js`). Что у них общего и что стоит
повторить:

- `destroy()` возвращает элемент в исходный вид: убирает слои, стили, слушатели;
- на тач-экранах и при «уменьшить движение» эффект выключен;
- добавленные слои не ловят клики (`pointer-events: none`) и скрыты от программ чтения с экрана;
- «Шифр» оставляет настоящий текст в `aria-label`.

## Общие настройки в сайдбаре

Нижняя часть правой панели («Общие») — не про конкретный эффект, а про рантайм. Что показывать,
решает одна функция — `commonSections()` в `engine/params.ts`. Правило: настройка видна, только
если рантайм этого эффекта её читает и она что-то меняет.

| Вид эффекта | Мышь | Инерция | Траектория | Качество, FPS | Пауза за экраном | Засыпание | Постобработка |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `quad`, `image` | да* | да* | да* | да | да | да | да |
| `quad` + `overlay` (курсор) | — | да | — | да | да | да | — |
| `slides` | да* | да* | — | да | — | с автопрокруткой | да |
| `three` | да* | да* | да* | да | да | да | — |
| `css`, `cursor`, `ui`, `transition` | — | — | — | — | — | — | — |

\* только при `usesMouse: true`.

Почему так: курсор без мыши — не курсор; слайдер рисует кадры только во время перехода, поэтому
точка по траектории не полетит; постобработка пишет непрозрачный кадр, а у курсора холст
прозрачный; у эффектов последней строки свои рантаймы, и общие настройки они не читают.

Новый `kind` → новая ветка в `commonSections()` и строка в её тесте (`params.test.ts`), а не
условие в `Controls.tsx`.

## Чек-лист перед коммитом

- [ ] Первый кадр красивый, без «разгона».
- [ ] Вертикальный экран: ничего не обрезано и не вытянуто.
- [ ] «Случайно» пять раз подряд — ни одного уродливого результата (иначе сузьте `min`/`max`).
- [ ] Пресеты различаются настроением, а не только цветом.
- [ ] У каждого неочевидного ползунка есть `hint`.
- [ ] `npm run check` и `npm run e2e` зелёные.
