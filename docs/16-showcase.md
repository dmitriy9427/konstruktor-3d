# 16. Витрина: страница из эффектов и GSAP

**Зачем это.** Главная страница проекта собрана из тех же эффектов, что отдаёт «Забрать код».
На ней видно, как несколько тяжёлых эффектов уживаются на одной странице, как связать их
с прокруткой и не уронить FPS. Код — [`src/site/main.ts`](../src/site/main.ts), разметка —
[`index.html`](../index.html), стили — [`src/styles/site.css`](../src/styles/site.css).

## Что на странице

| Секция | Эффект | Как связан с прокруткой |
| --- | --- | --- |
| Герой | «Сияние» + зерно и виньетка | Заголовок разбит на буквы (SplitText), блок уезжает и тает (`scrub`) |
| Сутки | «Волны», `cycle: 'scroll'` | Фон «прилип» (`position: sticky`), над ним едут 5 сцен; время суток — от прокрутки стека |
| Прожигание | переход «Прожигание» + «Огонь» под ним | Липкий стек: верхняя секция прогорает, пока стек прокручивается |
| Морфинг | 3D «Морфинг» | `ScrollTrigger` с `pin` и `scrub`: прогресс превращения = прогресс прокрутки |
| Фото | «Жидкая смена при наведении» ×3 | Карточки выезжают веером |
| Стекло | 3D «Стеклянные фигуры», поведение «мышь» | — |
| Финал | «Космос» + «Жидкая кнопка» | — |

Сверху — прелоадер (`mode: 'load'`), по всей странице — курсор «Падающая звезда» с кнопкой
выключения в шапке.

## Правило 1: всё тяжёлое — лениво

Двенадцать WebGL-контекстов сразу — это и долгий старт, и лимит браузера (обычно 16 контекстов).
Поэтому эффект создаётся, только когда его секция подъезжает к экрану:

```ts
function lazy(el: Element, start: () => void) {
  const io = new IntersectionObserver(([entry]) => {
    if (!entry.isIntersecting) return
    io.disconnect()
    start()
  }, { rootMargin: '100% 0px' }) // «за экран до появления» — успеет загрузиться
  io.observe(el)
}
```

Внутри `start` — динамический `import()`: рантайм и тем более three.js (≈ 185 КБ в gzip) скачиваются
только тогда, когда нужны. Уже созданный эффект не рисует, пока его не видно (`pauseOffscreen`
в рантайме), так что на экране одновременно работают 1–2 эффекта, а не все.

## Правило 2: pin создаём сразу, а не когда загрузится эффект

`ScrollTrigger` с `pin: true` добавляет секции «распорку» высотой в длину закрепления — страница
становится длиннее. Если создать pin позже, когда three.js догрузится, разметка поменяется прямо
посреди прокрутки: секция «уедет», а все триггеры ниже окажутся не на своих местах.

Поэтому триггер создаётся при загрузке страницы, а эффект подключается к нему, когда будет готов:

```ts
let progress = 0
let fx = null
ScrollTrigger.create({
  trigger: '#morph', start: 'top top', end: '+=150%', pin: true, scrub: true,
  onUpdate: (self) => { progress = self.progress; fx?.progress(progress) },
})
scene(stage, morph, values, (ready) => { fx = ready; fx.progress(progress) })
```

## Правило 3: SplitText — по словам, не только по буквам

Если разбить заголовок только на буквы (`type: 'lines,chars'`), каждая буква — отдельный
`inline-block`, и браузер может перенести строку **посреди слова**. Добавьте слова:

```ts
SplitText.create(el, { type: 'lines,words,chars', mask: 'lines' })
```

Слово — неразрывный блок, буквы внутри него по-прежнему анимируются. `mask: 'lines'` оборачивает
строку в блок с обрезкой: буквы «выезжают» из-под нижнего края строки. Обратная сторона:
слово шире колонки будет обрезано маской — поэтому размер шрифта подбирайте под ширину колонки.

Текст анимируется после `document.fonts.ready` (иначе строки посчитаются по запасному шрифту)
и после того, как прелоадер открыл страницу (`await loader.finished`).

## Правило 4: ничего не вылезает вбок

Холст огня у перехода больше секции: вокруг нужен запас под свечение и пепел. У секции на всю
ширину этот запас торчал бы за край окна, и у страницы появлялась горизонтальная прокрутка.
Рантайм перехода сам ограничивает запас по горизонтали краями окна. В тесте витрины это
проверяется явно: `document.documentElement.scrollWidth` не больше ширины окна.

## Правило 5: что прилипло — фиксируем

Пока «липкая» секция прилипла, она стоит на месте экрана, а её контейнер едет. Прокрутку
браузер двигает сам, в отдельном потоке, а JS узнаёт о ней только в следующем кадре. Если холст
огня лежит в контейнере и каждый кадр догоняет секцию через `transform`, он на кадр отстаёт и
**дрожит** даже при 60 FPS: в замере 30 кадров из 124 огонь съезжал на 60px. Поэтому, пока
секция прилипла, рантайм перехода ставит холст `position: fixed` на её место: и секция, и холст
стоят на экране неподвижно, догонять нечего.

## Доступность

- `prefers-reduced-motion: reduce` — нет прелоадера, нет анимации текста; эффекты рантайм сам
  ставит на паузу.
- Все холсты — `aria-hidden="true"`: это украшение, смысл — в тексте поверх.
- Курсор включается только при точном указателе (`pointer: fine`), на телефоне его нет.

## Тест

[`e2e/site.spec.ts`](../e2e/site.spec.ts) открывает главную, ждёт прелоадер, пролистывает все
секции и проверяет: холсты созданы, ошибок в консоли нет, горизонтальной прокрутки нет.
