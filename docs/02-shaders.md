# 02. Шейдер для самых маленьких

**Зачем:** понять, что написано в поле `fragment` у каждого эффекта, и уметь написать свой.

## Два шейдера: вершинный и фрагментный

Видеокарта рисует **треугольники**. Чтобы нарисовать что угодно, ей нужны две программы:

| | Вершинный шейдер (vertex) | Фрагментный шейдер (fragment) |
| --- | --- | --- |
| Вопрос | **Где** на экране вершины треугольника? | **Какого цвета** каждый пиксель внутри? |
| Сколько раз запускается | Один раз на вершину (у нас — 3 раза) | Один раз на пиксель (на Full HD — 2 миллиона раз за кадр) |
| На выходе | `gl_Position` — позиция вершины | `fragColor` — цвет пикселя |

```
   вершинный шейдер            растеризация              фрагментный шейдер
   «вот три точки»    ──▶   «вот какие пиксели      ──▶   «этот пиксель — синий,
                              внутри треугольника»          этот — чуть светлее…»
```

**В 3D-моделях** главная работа — в вершинном шейдере: он поворачивает модель, строит
перспективу, двигает частицы. **В наших фонах** фигура одна — прямоугольник на весь холст,
поэтому вершинный шейдер общий для всех эффектов и крошечный (`runtime.js`, константа `VERTEX`):

```glsl
#version 300 es
in vec2 aPos;                                       // координаты вершины из JavaScript
void main() { gl_Position = vec4(aPos, 0.0, 1.0); } // «оставь как есть»
```

Вся картинка рождается во фрагментном шейдере. Эффект пишет только его функцию `main()` —
всё остальное (версия, uniform, функции шума) рантайм дописывает сам (глава 03).

> В 3D-эффектах (рой, галактика, морфинг — глава [12](12-three.md)) роли меняются: позицию
> каждой из тысяч частиц считает **вершинный** шейдер, а фрагментный только рисует круглую
> светящуюся точку.

## Шаг 1. Один цвет

```glsl
void main() {
  fragColor = vec4(1.0, 0.0, 0.5, 1.0);   // r, g, b, прозрачность — от 0 до 1
}
```

Весь холст — розовый. Каждый пиксель выполнил эту программу и получил один и тот же ответ.

## Шаг 2. Цвет зависит от места

```glsl
void main() {
  vec2 uv = gl_FragCoord.xy / uResolution;   // где я? (0…1 по обеим осям)
  fragColor = vec4(uv.x, uv.y, 0.0, 1.0);
}
```

- `gl_FragCoord.xy` — координаты текущего пикселя в пикселях: (0, 0) … (ширина, высота).
- `uResolution` — размер холста (его передаёт рантайм).
- Делим — получаем `uv` от 0 до 1. Слева внизу чёрный, справа красный, сверху зелёный.

**Главная мысль:** шейдер — это **функция от координаты**. Пиксель не знает про соседей; он
только спрашивает «где я?» и отвечает цветом.

## Шаг 3. Пропорции

Холст обычно не квадратный: на экране 16:9 круг из `uv` вытянется в овал. Поэтому почти все
эффекты считают так:

```glsl
vec2 p = (gl_FragCoord.xy - 0.5 * uResolution) / uResolution.y;
```

- `- 0.5 * uResolution` — ноль в центре экрана;
- `/ uResolution.y` — одна единица = высота экрана по обеим осям. Круг остаётся кругом.

```glsl
void main() {
  vec2 p = (gl_FragCoord.xy - 0.5 * uResolution) / uResolution.y;
  float d = length(p);                          // расстояние до центра
  float circle = smoothstep(0.3, 0.29, d);      // 1 внутри, 0 снаружи, мягкий край
  fragColor = vec4(vec3(circle), 1.0);
}
```

`smoothstep(a, b, x)` — плавный переход от 0 к 1, когда `x` идёт от `a` к `b`. Самая частая
функция в шейдерах: мягкие края, затухания, пороги.

## Шаг 4. Время — и всё ожило

```glsl
void main() {
  vec2 p = (gl_FragCoord.xy - 0.5 * uResolution) / uResolution.y;
  float wave = sin(p.x * 10.0 + uTime * 2.0);   // волна бежит со временем
  fragColor = vec4(vec3(0.5 + 0.5 * wave), 1.0);
}
```

`uTime` — секунды с начала (рантайм прибавляет время каждый кадр). `sin` даёт −1…1, а
`0.5 + 0.5 * sin` — 0…1, как раз для цвета.

## Шаг 5. Свои параметры = ползунки

В описании эффекта:

```ts
params: {
  speed: { type: 'number', label: 'Скорость', min: 0, max: 5, default: 2 },
  tint:  { type: 'color',  label: 'Цвет', default: '#22d3ee' },
},
fragment: `
void main() {
  vec2 p = (gl_FragCoord.xy - 0.5 * uResolution) / uResolution.y;
  float wave = 0.5 + 0.5 * sin(p.x * 10.0 + uTime * uSpeed);
  fragColor = vec4(uTint * wave, 1.0);
}`
```

Рантайм сам объявит `uniform float uSpeed; uniform vec3 uTint;` — имя параметра с буквой `u`
и большой буквы. Цвет `#22d3ee` превращается в `vec3(0.13, 0.83, 0.93)`.

| Тип параметра | В шейдере | Что приходит |
| --- | --- | --- |
| `number` | `float` | число как есть |
| `color` | `vec3` | `#rrggbb` → три числа 0…1 |
| `boolean` | `float` | 1.0 или 0.0 |
| `select` | `float` | номер варианта: 0.0, 1.0, 2.0… |

## Шаг 6. Мышь

```glsl
float d = length((uv - uMouse) * vec2(uResolution.x / uResolution.y, 1.0));
col += vec3(0.3) * smoothstep(0.3, 0.0, d) * uMouseActive;   // светлое пятно под курсором
```

- `uMouse` — курсор в долях холста (0…1, y вверх, как у `uv`), уже **с инерцией**;
- `uMouseActive` — плавно 0 → 1, когда курсор над холстом (и обратно, когда ушёл);
- `uHover` — то же для наведения (картинки «плывут» только при наведении);
- `uScroll` — 0, когда блок только показался снизу, 1 — когда ушёл вверх.

## Шаг 7. Шум — «плавная случайность»

Случайное число на каждый пиксель даёт телевизионную рябь. Нужна случайность, которая **плавно
меняется**: соседние точки похожи.

```glsl
float hash(vec2 p) { return fract(sin(dot(p, vec2(127.1, 311.7))) * 43758.5453123); }
```

`hash` — «случайное» число 0…1 для точки. Одинаковая точка — одинаковое число (это важно:
кадр не мерцает).

```glsl
float noise(vec2 p) {
  vec2 i = floor(p), f = fract(p);           // номер клетки и место внутри неё
  vec2 u = f * f * (3.0 - 2.0 * f);          // плавный «вес»
  return mix(mix(hash(i), hash(i + vec2(1, 0)), u.x),
             mix(hash(i + vec2(0, 1)), hash(i + vec2(1, 1)), u.x), u.y);
}
```

Плоскость делится на клетки. В углах каждой — случайные числа (`hash`), между ними — плавное
смешивание (`mix`). Получается «холмистая» поверхность.

```
hash:   ▓ ░ █ ▒ ░ ▓ █     ← каждая клетка сама по себе
noise:  ▓▓▒░░▒▓██▓▒░░▒▓   ← плавные холмы
```

## Шаг 8. fbm — холмы на холмах

Природа не бывает «одного масштаба»: у облака есть большие клубы, на них — клубы поменьше,
на них — ещё мельче. fbm (фрактальное броуновское движение) складывает несколько шумов:

```glsl
float fbm(vec2 p) {
  float v = 0.0, a = 0.5;
  for (int i = 0; i < 5; i++) {
    v += a * noise(p);   // добавили слой
    p = p * 2.03 + ...;  // следующий — вдвое мельче
    a *= 0.5;            // и вдвое слабее
  }
  return v;
}
```

5 слоёв: крупный вклад + детали. Это основа «Облаков», «Шума», туманности «Космоса», краёв «Сияния».

## Шаг 9. Шум от шума (domain warping)

Самый эффектный приём — сдвинуть координаты шумом **перед** тем, как взять шум:

```glsl
vec2 q = vec2(fbm(p), fbm(p + 5.2));       // поле сдвигов
float n = fbm(p + 4.0 * q);                // шум в сдвинутых координатах
```

Формы начинают закручиваться, как дым или мрамор. Так сделан «Шум».

## Шпаргалка функций GLSL

| Функция | Что делает | Пример |
| --- | --- | --- |
| `mix(a, b, t)` | Смесь: t=0 → a, t=1 → b | `mix(синий, белый, 0.3)` |
| `smoothstep(a, b, x)` | Плавно 0→1 при x от a до b | мягкий край круга |
| `clamp(x, 0, 1)` | Зажать в диапазон | не дать цвету уйти за 1 |
| `length(v)` | Длина вектора | расстояние до центра |
| `dot(a, b)` | Скалярное произведение | освещённость: `dot(нормаль, свет)` |
| `fract(x)` | Дробная часть | повторяющийся узор |
| `floor(x)` | Целая часть | номер клетки |
| `sin`, `cos` | Волны | движение, вращение |
| `exp(-x)` | Быстрое затухание | свечение, дымка |
| `pow(x, n)` | Степень | узкий блик: `pow(…, 60.0)` |
| `normalize(v)` | Вектор длиной 1 | направление |
| `reflect(d, n)` | Отражение | блик на воде |
| `texture(img, uv)` | Цвет картинки в точке | «Плывущая картинка» |

## Частые ошибки

| Ошибка | Почему | Как надо |
| --- | --- | --- |
| `float x = 1;` | В GLSL `1` — целое, не `float` | `float x = 1.0;` |
| `vec3 c = 0.5;` | Нужен вектор | `vec3 c = vec3(0.5);` |
| Делить на `length(d)` | В центре длина 0 → бесконечность | `max(length(d), 1e-5)` |
| Цикл до переменной | Не во всех браузерах | Цикл до константы + `if (… ) break;` (см. «Лаву») |

Ошибку компиляции Студия показывает красным блоком прямо в превью — с номером строки.
