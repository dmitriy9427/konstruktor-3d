# 03. Рантайм: `src/runtime/runtime.js`

**Зачем:** это единственный код, который попадает в ваш проект. Разберём его сверху вниз.

## Почему обычный JS и без import

Студия вставляет **текст** этого файла в экспорт (глава 06). Поэтому:

- никаких `import` — файл должен работать сам по себе;
- обычный JavaScript, не TypeScript — экспорт не нужно компилировать. Типы для Студии лежат
  рядом в `runtime.d.ts`.

Плюс: превью и экспорт — **один и тот же код**. Нет второго, «упрощённого» движка, который
мог бы рисовать иначе.

## Карта файла

| Часть | Что делает |
| --- | --- |
| `VERTEX` | Общий вершинный шейдер (3 строки) |
| `COMMON` | Начало каждого фрагментного шейдера: общие uniform и функции `hash`, `noise`, `fbm`, `rot`, `coverUv` |
| `POST_FRAGMENT` | Шейдер постобработки (глава 05) |
| `uniformName`, `hexToRgb`, `uniformValue` | Перевод параметров в uniform |
| `buildFragment(spec)` | Склейка полного текста шейдера эффекта |
| `createEffect(canvas, spec, options)` | Запуск эффекта, всё остальное — внутри |
| `defaultsOf(params)` | Значения по умолчанию из описания |

## 1. Сборка шейдера: `buildFragment`

Эффект пишет только `main()`. Рантайм приклеивает всё остальное:

```js
buildFragment({ fragment: 'void main() { … }', params: { speed: {type:'number'}, tint: {type:'color'} } })
```

даёт:

```glsl
#version 300 es              // GLSL ES 3.0 (WebGL2)
precision highp float;       // ┐
uniform vec2 uResolution;    // │
uniform float uTime;         // │ COMMON — одинаковое
uniform vec2 uMouse;         // │ для всех эффектов
…                            // │
float fbm(vec2 p) { … }      // ┘
uniform float uSpeed;        // ┐ из params эффекта
uniform vec3 uTint;          // ┘
out vec4 fragColor;          // куда писать цвет
void main() { … }            // ← fragment эффекта
```

Для эффектов картинки добавляется `uniform sampler2D uImage; uniform vec2 uImageRes;`.

## 2. Запуск: `createEffect`

```js
const effect = createEffect(canvas, spec, { mouse: true, quality: 1.5, post: { grain: 0.2 } })
```

### Контекст

```js
const gl = canvas.getContext('webgl2', { antialias: false, alpha: false, … })
if (!gl) throw new Error('WebGL2 недоступен')
```

- `antialias: false` — сглаживание краёв не нужно: у нас нет краёв, весь холст — один шейдер;
- `alpha: false` — холст непрозрачный, браузеру проще смешивать его со страницей.

### Компиляция

`compile()` отдаёт текст видеокарте; если в шейдере ошибка — бросает
`Ошибка шейдера: <лог видеокарты>`. Студия ловит её и показывает красным блоком.
`link()` соединяет вершинный и фрагментный шейдер в «программу» и кеширует места uniform
(`getUniformLocation` — дорогой вызов, делать его каждый кадр незачем).

Программ две: `main` (эффект) и `post` (постобработка).

### Один треугольник вместо прямоугольника

```js
new Float32Array([-1, -1,   3, -1,   -1, 3])
```

Экран в WebGL — квадрат от −1 до 1. Прямоугольник — это два треугольника. Но можно взять **один
большой** треугольник, который накрывает экран целиком, а лишнее видеокарта сама отрежет:

```
(-1,3)
  │\
  │  \
  ├────\ (1,1)
  │экран│\
  │     │  \
  └─────┴────\
(-1,-1)       (3,-1)
```

Чуть быстрее: нет шва по диагонали, где пиксели считались бы дважды.

## 3. Картинка-текстура

`loadImage(источник)` принимает адрес или `<img>`. Когда картинка загрузилась —
`texImage2D` копирует её в видеокарту. `UNPACK_FLIP_Y_WEBGL` переворачивает её: у картинок
y растёт вниз, у WebGL — вверх. `CLAMP_TO_EDGE` — на краях картинка не «заворачивается».

Шейдер берёт координаты через `coverUv(uv, размерБлока, размерКартинки)` — как CSS
`object-fit: cover`: картинка заполняет блок без искажения пропорций.

## 4. Размер и плотность пикселей

```js
const dpr = Math.min(devicePixelRatio, opts.quality) * adaptiveScale
canvas.width = rect.width * dpr
```

- На экране с DPR 3 холст 1000×600 CSS-пикселей — это 3000×1800 = **5,4 млн** пикселей.
  С `quality: 1.5` — 1500×900 = **1,35 млн**: вчетверо меньше работы. Мягкие фоны выглядят
  так же.
- `ResizeObserver` следит за размером элемента — холст подстраивается без обработчика `resize`.

### Адаптивное качество

```js
if (dt > 0.024) {                 // кадр дольше 24 мс (ниже ~40 FPS)
  if (++slowFrames > 30)          // и так полсекунды подряд
    adaptiveScale -= 0.15         // снижаем плотность (но не ниже 0.5)
}
```

Слабый ноутбук сам получит более «мягкую» картинку вместо дёрганой анимации.

## 5. Мышь с инерцией

```js
pointer.tx = (clientX - rect.left) / rect.width     // цель: где курсор сейчас
// каждый кадр значение догоняет цель:
const k = 1 - Math.exp(-dt / inertia * 0.25)
pointer.x += (pointer.tx - pointer.x) * k
```

Почему `1 - exp(...)`, а не просто `0.1`? Потому что при 120 FPS кадр вдвое короче, чем при 60, и
шаг «0.1 за кадр» дал бы вдвое более быструю мышь. Формула с `dt` даёт одинаковую плавность
на любом мониторе. Время «догоняния» — примерно `инерция × 4` секунды.

Если «Следовать за мышью» выключено — цель всегда центр (0.5, 0.5), а `uMouseActive` плавно
уходит в 0.

Слушаем `pointermove` на всём окне, а не на холсте: холст часто лежит **под** текстом
(`z-index: -1`), и события до него не доходят.

### Траектория

Опция `path: { points, closed, speed, mode }`. Пока мыши нет над эффектом (или всегда, если
`mode: 'always'`), цель мыши — точка на пути, и всё, что эффект делает с мышью, делает путь.

```js
pathTime += dt * speed * 0.1                       // speed — кругов за 10 секунд
;[tx, ty] = pathPoint(points, closed, pathTime)
```

`pathPoint` — кривая Катмулла — Рома через точки: путь плавный, без углов. Время на каждый
отрезок — по его длине, поэтому скорость вдоль пути примерно постоянная. Открытый путь идёт
туда и обратно. Траектория не новая логика для каждого эффекта, а **подмена мыши** — поэтому
она сразу работает у всех.

## 6. Цикл кадров и экономия

```js
function tick(now) {
  time += dt          // если не «уменьшить движение» и не на паузе
  …двигаем мышь…
  draw()
  if (running() || settling) requestDraw()   // нужен следующий кадр?
}
const running = () => !destroyed && visible && !paused && !opts.reducedMotion
```

Кадр запрашивается, только если он нужен:

| Ситуация | Что происходит |
| --- | --- |
| Эффект за экраном | `IntersectionObserver` ставит `visible = false` → кадры не рисуются вообще |
| «Уменьшить движение» в системе | Время стоит, рисуется один кадр (и при изменении параметров) |
| `pause()` | Время стоит |
| Поменяли параметр (`set`) | `requestDraw()` — нарисовать один кадр с новыми значениями |
| Наведение ещё «доезжает» | `settling` — рисуем, пока `uHover` не дойдёт до цели |

`time` начинается не с 0, а с `startTime` (по умолчанию 4): у многих эффектов первые секунды —
«разгон», а нам нужен красивый первый кадр.

### Засыпание и потолок FPS

```js
const awake = () => !opts.sleepAfter || performance.now() - lastActivity < opts.sleepAfter * 1000
const running = () => … && awake() && …
```

`lastActivity` обновляют `pointermove`, `pointerdown`, `wheel`, `scroll`, `keydown`,
`touchstart` — с `capture: true` на окне, поэтому ловится прокрутка любого блока. Пользователь
ушёл пить чай — через `sleepAfter` секунд кадры прекращаются. Вернулся и шевельнул мышью — первое
же событие будит эффект.

**Потолок FPS:** если с прошлого кадра прошло меньше `1000 / maxFps` мс, кадр пропускается —
просто ждём следующего обновления экрана:

```js
if (opts.maxFps > 0 && last && now - last < 1000 / opts.maxFps - 2) {
  frame = requestAnimationFrame(tick)
  return
}
```

(`− 2` мс — запас: экран 60 Гц даёт кадры через 16,6 мс, и без запаса при `maxFps: 60` мы бы
пропускали каждый второй.)

**Время идёт только пока анимация запущена** (`if (running()) time += dt`). Иначе разовая
перерисовка у спящего эффекта (изменился размер окна, поменяли параметр) сдвигала бы картинку
на кадр — заметный «дёрг». Эту ошибку поймал e2e-тест засыпания.

## 7. Отрисовка: `draw()`

1. Если включена постобработка — рисуем в FBO (невидимый холст), иначе — прямо на экран.
2. Передаём общие uniform: `uResolution`, `uTime`, `uMouse`, `uMouseActive`, `uHover`, `uScroll`.
3. Для каждого параметра: `uniformValue` → `uniform1f` (число) или `uniform3fv` (цвет).
4. `drawArrays(TRIANGLES, 0, 3)` — один треугольник.
5. Если была постобработка — второй проход: FBO как текстура → шейдер `post` → экран.

## 8. Время видеокарты

`performance.now()` меряет только JavaScript. Сколько работала **видеокарта**, узнаём через
расширение `EXT_disjoint_timer_query_webgl2`: «запрос» вокруг отрисовки, ответ приходит через
кадр-другой (видеокарта работает асинхронно). Если ответ «disjoint» (например, ноутбук
переключил частоту) — замер выбрасываем. Расширения нет в Safari и Firefox — там `gpuMs: null`.

## 9. Уничтожение

`destroy()` снимает все обработчики и наблюдатели, удаляет программы, буферы, текстуры и
вызывает `WEBGL_lose_context.loseContext()` — **отпускает контекст сразу**. Браузер разрешает
около 16 контекстов WebGL одновременно; без этого при переключении эффектов в Студии можно
быстро упереться в лимит.

Следствие: после `destroy()` холст использовать нельзя. Поэтому `mount()` и превью Студии
каждый раз создают **новый** `<canvas>`.

## API целиком

```ts
createEffect(canvas, spec, options?) → {
  stats,                   // fps, cpuMs, gpuMs, dpr, drawCalls, width, height
  set(values),             // поменять параметры эффекта
  setOptions(options),     // mouse, inertia, quality, post, adaptive, reducedMotion
  setImage(srcOrImg),      // новая картинка
  play(), pause(),
  destroy(),
}
```

| Опция | По умолчанию | Смысл |
| --- | --- | --- |
| `mouse` | `true` | Следовать за мышью |
| `inertia` | `0.12` | Инерция мыши |
| `quality` | `1.5` | Потолок DPR |
| `adaptive` | `true` | Снижать плотность при просадке FPS |
| `reducedMotion` | из системы | Один неподвижный кадр |
| `pauseOffscreen` | `true` | Не рисовать за экраном |
| `sleepAfter` | `0` | Засыпать через столько секунд без действий пользователя (0 — никогда) |
| `maxFps` | `0` | Потолок кадров в секунду (0 — сколько даёт экран) |
| `path` | `null` | Траектория «точки влияния» |
| `scrollStack` | — | «Липкий» стек: `uScroll` — насколько он прокручен (иначе — как блок проезжает через экран) |
| `scroller` | окно | Контейнер прокрутки |
| `post` | всё 0 | `{ grain, chroma, vignette, bloom }` |
